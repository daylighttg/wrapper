Public mode, one port for the panel and the API, request statistics, and
backup / migration.

## New

- **One port.** The panel and the wrapper-lite API now share
  **Settings → Network** (default `http://127.0.0.1:12340`); port 12341 is
  gone. Clients keep using the same address. Changing the listen address
  applies at once, without restarting the engine.
  - On this machine the panel opens directly. Other machines sign in with the
    management token (or open the `?token=` URL wrapper prints). Requests
    relayed by a local reverse proxy, sent by other websites or through
    DNS rebinding are not trusted as local.
  - The headless agent (`wrapper agent`, Docker) serves the panel on its API
    port too; sign in with `--api-token`. `--no-ui` turns it off.
- **Public mode** (panel → **Public mode**, or `wrapper agent --public
  --max-accounts N`, Docker: `WRAPPER_PUBLIC=true`): anyone who opens your
  address can add their own Apple Music account (with 2FA) and remove it
  again.
  - Visitors see a public page: status, regions, request statistics, the
    account list with masked names (`jo***@g***.com`) and a login form. Apple
    IDs, logs, settings and the token stay hidden.
  - **Maximum active accounts** keeps a small machine from running out of
    memory (each logged-in account is a lite process, about 150 MB).
    Accounts that need a new login do not take a slot; accounts you add
    yourself are not limited.
  - Each public login hands out a **logout key** (remembered by the browser).
    Logging out needs the Apple ID and that key, so visitors cannot remove
    each other's accounts.
  - An Apple ID that is serving cannot be logged in again publicly; at most
    two public logins run at a time, six per address per 30 minutes.
  - Optional notice text on the public page.
- **Request statistics** per endpoint (`/m3u8`, `/key`, `/lyrics`,
  `/webplayback`, `/license`) and per account, today and in total, with a
  30-day chart, on the dashboard, the accounts page and the public page
  (`GET /api/stats`).
- **Backup and migration** (panel → **Backup**):
  - Download one `.tar.gz` with every account's login session, the
    public-mode settings and the statistics. Restored accounts come up
    without logging in again, with the same device identity.
  - Restore by **merging** or **replacing everything**.
  - **Directly from another server**: give the new server the old address and
    token and it fetches the backup itself.
  - Command line: `wrapper backup`, `wrapper restore <file>`,
    `wrapper restore --from http://old:12340 --from-token <token>`.
  - A backup lets anyone use its accounts: keep it private.

## Upgrading

`wrapper update` (stop the panel first). Update the binary **and** the QEMU
guest / rootfs together (the default), since the new panel needs the new
agent.

- Open the panel at `http://127.0.0.1:12340` instead of `:12341`.
- `wrapper gui --host/--port` now set the address of the panel *and* the API
  (and are saved). If a script started `wrapper gui --port 12341`, drop the
  option or the API moves to 12341.
- With **Listen on** set to `0.0.0.0`, the panel is reachable from your
  network too, behind the management token.
- Android: install the new APK. Docker: rebuild the image (it now includes
  the panel).
